# technical-analysis — 技术面研判（架梯动力学）

独立 skill：五维研判「技术面」维度的研判能力，落点属**知识层**——消费 chanlun_dll 实时算好的结构数据（投研取数模块 `scripts/struct_calc.py`：vipdoc+本地前复权主源 / MCP 备源 → `CL_ExportStruct` 五实体，字段语义同分片库六表）与量化因子，产出**供人决策的论据**（架梯分型 / 挂坡 / 强势起步 / 背驰 / 强弱），供五维共振与深度投研报告使用。

> 本 skill 为独立技术面研判能力；`internal/技术面/**` 相对引用在本 skill 目录内解析。

## 能力与角色

- **能力**：先读结构骨架定位「在哪」（中枢 / 笔段路连接），再读量化因子回答「多强」（量能 / 动能 / 空间 / 突破真假），综合出「架梯分型 / 挂坡 / 强势起步 / 背驰 / 强弱」研判论据。
- **角色**：技术面维度（五维之一）。
- **不是**：结构计算（归 chanlun_dll）、信号检出（归 DLL 检出层）、1-100 评分 / 榜单硬排序（禁止）。

## 符号体系（架梯动力学）

- **五定点 A/B/C/D/E**：A = 起点（前腿起点 = 背驰拐点）、B = 起点左侧同级别高点（过前高参照）、C = 高点（前腿终点 = 后腿起点）、D = 终点（后腿低点 = **挂坡点**）、E = 第三腿**强势起步**（买点）。
- **成立条件**：C > B 且 60 线首次上翘。
- **级别符号**：挂坡点 D⁺/D/D⁻（大/本/次）、强势起步 E⁺/E/E⁻；锚接 D⁺≡A、D≡A⁻，成功的 E 点永远跟在 D 点后（本级别 D→E 演绎次级别 A⁻→E⁻）。
- **买点铁律**：买点 ≠ 第三腿突破（突破翻箱、盈亏比约 1:1），= 第三腿强势起步（归纳 = 本级别两根大阳线 / 演绎 = 次级别架梯成色）。

## 结构骨架（势与形）+ 注入点

技术面研判的骨架是**结构**，注入点是**结构的属性**。结构分「势」与「形」两类，每个结构下按需挂「成色 / 刻度 / 止损止盈」三类注入点（骨架定义 + 四段式约定见 `internal/技术面/结构/README.md`）：

| 类 | 结构 | 注入点 | 回答（技术维三层述求） |
|---|---|---|---|
| 势 | 月线 | 成色（看空间） | 值不值得分析 · 空间 |
| 势 | 周线 | 成色（看方向） | 值不值得分析 · 方向 |
| 形 | 架梯套 | 成色 | 值不值的等（新生趋势成色，已发生事实） |
| 形 | 区间套 | 成色 | 值不值的等（衰竭成色，已发生事实） |
| 形 | 端子 | 成色（第三腿起步第一棒） | 现在能不能做（入场，只对买入负责） |
| 形 | 第三腿 | 成色 + 刻度 + 止损止盈 | 买 / 持 / 卖（持仓管理） |

- **坐标**（A/B/C/D/E 定点）= 结构本身，硬编码。
- **演化**（闸门递归：成坡→挂坡→点火）= 结构骨架，硬编码。
- **记录**（级别归属留证 `frac_idx/frac_date`）= 全局纪律，每条研判结论都带。

## 研判流程（详见 internal/技术面/推理规则.md）

**先走主轴 → 因子清单选因子 → 审美定强弱 → 套规则**：

1. **套切入点主轴**：先定基准点 → 左验结构 → 右捕时机 → 判新鲜度（推理规则.md 第〇部分）。
   - 多周期心法：**月线看空间、周线看方向、日线看位置、30 分钟看买点，顺大逆小、高空低多、所见即所得**。
2. **按注入点锚字段选因子**：读 `bi_frac` 四量化列 + `kline` 指标列 + `zhongshu`，只选因子读值、不打分。
3. **审美定强弱**：查统一极性表取三态极性，Σ(w×极性) 得相对排序论据（结论层，可调校）。
4. **套规则判定**：规则 1-12 逐条套用，产出研判论据（非信号 / 非分数）。

## 数据获取

- **取数**：`scripts/struct_calc.py`（投研取数模块，chanlun_dll 实时算单标结构）。
  ```sh
  python scripts/struct_calc.py 600519 day 250     # 日线结构
  python scripts/struct_calc.py 600519 month 200   # 月线
  python scripts/struct_calc.py 600519 m30 100     # 30 分钟
  ```
- **配置**：`config/runtime.env.example` → 部署机复制为 `config/runtime.env`（或环境变量 `TA_RUNTIME_ENV` 显式指向）；最小只需 `TDX_ROOT`。**chanlun64.dll 已随包 `vendor/` 分发**（x64 静态链接，默认命中，无需配置；仅覆盖时才设 `CHANLUN_DLL_PATH`）。
- **字段语义真相源**：结构数据字段语义（六表契约）随本 skill 内联摘要；字段 → 锚定见 `internal/技术面/config/feature_anchor.json`。

## 环境就绪检查与配套引导（调用前置 · 必做）

> 目标：**每次调用本 skill 前，先自检运行时配套；缺失时在会话中主动声明并请用户提供路径**，而不是等到取数报错。

**步骤 1 · 自检**：先跑环境自检脚本（复用 struct_calc 的路径解析，无第三方依赖）：

```sh
python scripts/env_check.py            # 人类可读报告（含 JSON 摘要行 __ENV_CHECK_JSON__）
python scripts/env_check.py --json    # 机器可读 JSON（LLM 解析用）
```

**步骤 2 · 按结果分流**：

- `ready: true`（所选数据源 + chanlun64.dll + 目标解释器依赖就绪）→ 直接进入研判流程；`optional-missing` 项（gbbq）在报告中标注即可，不阻塞。
- `ready: false`（存在 `missing`/`invalid` 硬缺失）→ **优先引导用户在页面配置**（路径 A），会话内 `--write` 为备选（路径 B）：
  1. **路径 A（推荐）**：提示用户到 **设置 → 技术面研判 → 环境设置** 页填写缺失项（数据源复选框 + 按勾选填路径/token + 保存），保存后自动落盘 runtime.env；告诉用户保存完成后回来，我重检继续；
  2. **路径 B（会话内）**：用户也可直接在此提供路径/token，用 `--write` 落盘并重检：
     ```sh
     python scripts/env_check.py --write="KLINE_SOURCES=..." --write="TDX_ROOT=D:\..." --write="TDX_MCP_TOKEN=..."
     ```
  3. 重检 `ready: true` → 继续研判；仍缺失 → 走「降级纪律」。

**数据源（复选框，`KLINE_SOURCES` 承载）**：vipdoc / tdx-mcp **两个独立勾选**（可多选），勾选哪个就要求配置哪个：

| 勾选 | KLINE_SOURCES | 需要用户提供 |
|---|---|---|
| ✅ vipdoc | `vipdoc` | 通达信根目录 `TDX_ROOT`（vipdoc/gbbq 由其内部子目录推导） |
| ✅ tdx-mcp | `tdxmcp` | MCP token `TDX_MCP_TOKEN`（**用户自备，无通用 token**，机密写页面） |
| ✅✅ 两者 | `vipdoc,tdxmcp`（默认） | `TDX_ROOT` + `TDX_MCP_TOKEN` 都要 |

> 勾选联动：选 vipdoc 才需要 TDX_ROOT，选 tdx-mcp 才需要 token，未选源自动 `skipped`。`chanlun64.dll` 已随包 vendor/ 分发；VIPDOC_ROOT/GBBQ_PATH 由 TDX_ROOT 推导、CHANLUN_DLL_PATH 不提供配置——均无需用户提供。

**解释器与 venv 供给（用户可控，不自动装）**：插件需要 **Python ≥3.10 解释器**（PEP 723）；目标机器无 python 或要跨机可控时，**推荐在设置页显式指定 `VENV_PYTHON` 绝对路径**：

| 方式 | 做法 |
|---|---|
| **A. 显式指定解释器（推荐）** | 用户在设置页填 `VENV_PYTHON`（python/venv 的**绝对路径**，如 `D:\...\venv\Scripts\python.exe`），或 `--write="VENV_PYTHON=D:\...\python.exe"` 后重检；env_check 会用该解释器探测版本与依赖 |
| **C. 当前解释器（未配置时兜底）** | 不配 VENV_PYTHON → 用 `sys.executable`（env_check **显示其绝对路径**，便于确认）；依赖缺失由用户确认后手动 `python -m pip install numpy pandas requests` |

> 无 python 环境时：`python --version` 失败 / env_check 无法运行 → 引导用户到设置页 VENV_PYTHON 填解释器路径，或安装 Python ≥3.10 后重试。依赖清单在设置页已备注；不会装时引导复制工作提示词「**本地环境依赖检查与安装**」（只检测+给命令，不自动执行）。

**配套声明模板**（会话中向用户展示）：

> 本插件（dsh-stock-jt · 技术面研判）缺少运行配套，请在 **设置 → 技术面研判 → 环境设置** 页配置（推荐）：
> - ❓ **数据源（复选框）**：勾选本地 vipdoc → 填 TDX_ROOT；勾选云端 tdx-mcp → 填自备 token；都勾 = 双源
> - ❓ **Python 解释器**：需要 ≥3.10——指定 VENV_PYTHON 绝对路径（推荐，跨机可控），或确认当前解释器可用（env_check 显示其路径）
> - ⚠️（可选）Python 依赖 numpy/pandas/requests——缺时按工作提示词「本地环境依赖检查与安装」手动装
> 保存后告诉我，我重检继续；若不便到页面，也可直接在此提供路径/token（token 请写入页面，不回传明文）。

**红线遵守**：自检/写盘只经 `env_check.py --write`（原子替换）、环境变量或**设置页 POST**（服务端原子写，token 脱敏）；**不自动安装任何依赖**（安装由用户确认后手动执行）；不引导用户在会话中明文粘贴机密 token（token 要求写入设置页或部署机 runtime.env，不回传明文）。

## 降级纪律

- 结构数据不可得（取数模块失败 / 主备源均不可用）→ **技术面维度降级**：简报标注「本周期结构数据缺失，技术面结论置信度相应下调」，不报错、不阻断主线；降级留痕（reports/ 标注），保证可审计。

## 红线（四条硬约束）

1. **双轨制**：只解读，不计算、不检出、不改结构。
2. **三条禁止**：不产出信号检出结论 / 不作固化量化分数（1-100 评分、榜单硬排序）/ 不覆盖原始共振检出集合。
3. **可追溯**：每条推理规则锚定 `表.字段 + 因子值`。
4. **自包含**：本 skill 不含盘符绝对路径链接（数据路径一律走 config 环境变量）。

## 输出规范

- 每条研判结论须带字段证据（如 `zhongshu.zg/zd`、`bi_frac.macd_area` 具体值）。
- 阈值一律引用领域经验值（出处见《推理规则.md》附：阈值来源表，已脱敏），不硬编码为绝对常量。
- 结论表述为「论据 + 置信度」，不作 0/1 信号。
